# 规则手册（RULES）：大阪城浏览器模型的物理不变量与审计

> 适用版本：web-r4 起。代码：`web/site.js`（场地规格、生成、H 系列审计）、`web/camera.js` + `web/app.js`（相机物理体、C 系列审计）、`tests/test_web.py`（无头浏览器验收）。

## 0. 总体思路

1. **布局是约束，不是变量。** 曲轮、护城河、石垣脚线、现存建筑的平面全部来自 OpenStreetMap 实测（`data/osm.json` → `data/castle_layout.json` → `web/data.js`）。规则只能在实测布局内**推导**部件的位置（吸附、截断、推出），不允许为了让审计通过去手改坐标。
2. **规则 = 抽象的物理不变量。** 这不是一个有物理引擎的世界，所以“物理”写成几何不变量：支撑（底面落在承载面上）、接触/闭合（墙端顶到实体，防线无缝）、通行（人能走过去）、净空（球体/人体不与几何相交）、排水（之后加入）……它们不抄任何建筑法规的条文。
3. **历史惯例只定参数。** 1 間 ≈ 1.97 m、扇勾配约 0.22×高、土塀高 2.2 m、枡形 = 高丽门 + 直角渡橹门、角橹在石垣转角——这些只决定规则里的数字或者“族”的选择，不改变规则的形式。
4. **生成按构造满足，审计用通用算法独立复查。** 生成器按规则把部件放对；审计**不复用生成器的中间结果**，而是用独立的采样、接触图、栅格寻路、三角形精确距离去检查结果，所以生成器写错时审计能抓到。每次构建全部审计必须为 0；每条新规则都要有“故障注入”证明它能报出违规。
5. **视觉只管好看。** 渲染（材质、砌石着色器、屋顶造型）不参与任何判定；所有判定都基于规格几何（多边形、高度网格、碰撞三角形），所以“看起来对”不能替代审计，审计为 0 也不代表外观已经满意（见第 4 节路线图）。

坐标：本地米制，原点 = 天守，x 东、y 北、z 上（渲染时换成 three.js 的 x, z, −y）。

## 2. 硬规则 H1–H14（`site.js` 的 `audit()` / `physics()`）

每条：**不变量** · 参数 · 容差 · 计算方法 · 设计理由。计数单位是“违规项”，面板里违规部件标红。

### H1 建筑底面贴地
- 不变量：每个有平面的部件（门、橹、建筑、天守），底面上任意点的地形高度 = 部件底标高。
- 容差 |Δz| < 0.1 m；另外地基整平被拒（与坡道/水面冲突）的格点数 > 0 也算违规。
- 计算：多边形内 1 m 采样 + 边界采样，`heightAt`（与渲染同剖分的三角插值）。
- 理由：生成时 `settle` 已整平，审计独立采样检查“确实整平了且没被后续操作改掉”。

### H2 不穿插
- 不变量：建筑之间、建筑与墙、墙与墙、树与建筑不重叠。
- 容差：多边形各内缩 0.05 m 再判面积重叠；墙端斜抵到某个面时，允许 t/2·cotφ 的一角顶入（φ = 墙轴与被抵面的夹角，上限 2t），这是**抵接**不是穿插；两段墙端都是 `joint` 且相距 ≤0.2 m 视为斜接。
- 计算：一般多边形（可凹）边相交 + 顶点包含测试；包围盒预筛。

### H3 墙底在台地顶
- 不变量：土塀/枡形墙沿轴线及两侧面 1 m 采样，地形高 = 墙底标高。
- 容差 0.1 m。

### H4 坡道两端同高且坡度合规
- 不变量：坡道/桥起点 = 出发曲轮标高，终点 = 目标曲轮标高（端点本身和端点外 0.6/1.0 m 的地面都要等高）；坡度 ≤30%。
- 理由：坡道两端是“接缝”，最容易出现台阶或悬空。

### H5 门有路、门洞通畅
- 不变量：每座非内门都有通到 `to` 曲轮的坡道/桥；坡道中线 `surfaceAt` 与剖面一致（断开 <0.15 m）；门洞前后通道（门洞宽 ×0.9，门深 +12 m）里没有墙。内门两侧 4 m 处为同层地面。

### H6 不落水
- 不变量：建筑/墙/树/坡道面高于水面 +0.3 m。

### H7 曲轮高程
- 不变量：每个曲轮内部（离石垣顶线 >3 格、离坡道放坡带和建筑 >3 m）60 个随机采样的高度 = 规格标高（±0.01 m）。
- 理由：防止某个操作（放坡、整平）意外改动大片平台。

### H8 在曲轮内
- 不变量：部件底面采样点都在所属曲轮（含外圈分离后的归属）内。

### H9 水面只被土桥改
- 不变量：原本是水底（不属于任何曲轮）的格点，高度只允许被土桥路面/放坡（TAG 2/3）改动。

### H10 引用全部解析
- 不变量：规格里所有引用（建筑名、遗址点、方向最远点）都能解析；所有门都已放置；生成器的 `notes`（例如颈切线找不到、围合线断开）计为违规。

### H11 支撑（物理）
- 不变量：部件**整个底面**（内缩 0.3 m）落在本曲轮的台地顶面上——不悬空、不压在石垣斜面上；墙底沿轴线 0.5 m 采样、两侧面各一条；树根处地面坡度 ≤30% 且树根高 = 地面高（±0.05 m）。
- 计算：`onTop(g,x,y)` = 区域归属正确 ∧ 在围合线内 ∧ 石垣顶线距离场 `crestDist ≥ 0`。
- 理由：r1 布局的主要错误是墙端悬空在石垣斜面上（171 处），H1 的高度采样抓不到“恰好等高但下面是斜面”的情况，所以单独用顶线距离场判。

### H12 闭合（物理）
- 不变量：① 每个墙端在 0.2 m 内顶到另一段墙端/墙体/门/建筑；② 防御线（土塀轴线）0.5 m 采样全部被土塀/门/建筑覆盖，连续缺口 ≤0.6 m；③ 没有 <1 間 的碎墙（土塀 run 和枡形墙）；④ 枡形方院门关上后封闭：从方院中心在 0.5 m 栅格上洪泛（建筑/墙/坡度 >30% 的陡坎/水都是障碍），走不出方院外 8 m。
- 设计理由（**槽位链防御线**）：r1 是“先放建筑，再在墙上开口”，开口和建筑总对不齐。r2 起，防御线 = 曲轮外边界 → 逐边内缩 B 得石垣顶线 → 再内缩 0.9 m 得土塀轴线（斜接内缩 + 自交切除 + 按距离场修正深石垣端头）。门和建筑先占位，然后沿轴线做**槽位序列**：被占住的区间之外**全部**是土塀，每段土塀端头正好落在相邻部件的面上，转角斜接。这样闭合是**按构造**成立的，H12 只是独立复查。

### H13 石垣边（物理）
- 不变量：离石垣顶线 <3 m 的建筑，外墙面要么与顶线齐平（≤0.3 m），要么退后但前方有土塀；外挑出顶线 ≤0.3 m。
- 理由：避免“橹和石垣边之间留一条人能掉下去的缝”或“橹悬在石垣外”。生成侧对应规则：现存橹按“面贴边”平移，失传橹吸附到最近石垣并在转角处滑到角上，非直角转角沿主边滑开。

### H14 通行（物理）
- 不变量：从每座门的门洞中心出发，在 0.5 m 栅格上（坡度 ≤30%、离障碍的距离 ≥ 门洞半宽 − 0.6 m）向外能走到坡道/桥另一端（3 m 内）、向内能走到离门 ≥45 m 的本曲轮地面；内门两侧都能走到 20 m 外；坡道轴线穿过门洞中心（≤0.3 m）且垂直于门（|cos| ≤0.05）；坡道宽 ≥ 门洞。
- 计算：`surfaceAt`（地形与桥面取高者）→ 陡坎标障碍 → 部件多边形（扣除 `passages` 门洞）标障碍 → 两遍扫描的倒角距离变换得净宽 → DFS 洪泛。
- r1 布局在 H11–H14 下共 194 项违规（171 悬空墙端、19 石垣边缝/外挑、3 座门内走不通）。

## 3. 相机规则 C1–C7（`camera.js` + `app.js` 的 `cameraAudit()`）

### 设计：相机 = 自由空间里的球
- **为什么是球**：r2 的相机是一个点，切换视角时会穿进地面和建筑。r3 把相机做成半径 R = 1.5 m 的球，碰撞场由**真实渲染几何**（全部三角形保守栅格化）派生，而不是由规格多边形估算——看见什么就撞什么。
- **为什么是精确间隙**：r3 的柱状场（每格“球心最低高度”）让球心永远高于门楣/桥面，钻不进门洞。r4 改为精确间隙：三角形 3D 空间哈希（4×4×6 m 桶）+ 地形三角网（与渲染同剖分）+ 水面 + 树（树干/树冠真包围盒）。球心合法 ⇔ 到一切几何距离 ≥ R。柱状场保留为**充分条件快速通道**（球心高于它必合法）。
- **可达性**：自由空间 = 从天空出发、球体连续运动能到达的点。每帧扫掠（0.5 m 采样 < 2R，零厚度面也穿不过）+ 二分接触 + 沿接触面切平面滑移；瞬移要求落点“向上开放”（竖直扫掠到柱状场之上全程合法），所以球不会出现在封闭建筑内部。
- **视角 = 规则**：每个视角只写目标点、方位角、仰角、距离、目标本体半径 rf；相机位置由规则推出，不清空/被挡时按代价搜索最近的清空且通视位置。
- **近平面**：取使近平面四角到相机 ≤0.9R 的最大值（球保证几何离相机 ≥R，近处墙面不会被切掉）。

| 规则 | 不变量 | 参数 / 容差 | 计算方法 |
|---|---|---|---|
| C1 | 每个视角的相机球心合法（不在实体/地下/水下） | 间隙 ≥ R − 0.001 | `valid()`；独立校验 `geoCheck`（三角形 2D 哈希 + 球-三角形精确距离 + 地形 + 封闭性 17 条射线） |
| C2 | 相机→目标视线无遮挡 | 目标周围 rf 内不算遮挡 | 线段 vs 地形 0.5 m 采样 + 三角形 Möller–Trumbore + 树盒 slab |
| C3 | 任意两视角之间的过渡路径全程合法 | 0.25 m 采样 | 直线 → 门洞端点 3D 栅格逃逸 → 精确最小抬升包络 → 柱状包络兜底；逐点 `valid` |
| C4 | 随机旋转/缩放/平移/穿过目标推拉/全城瞬移后相机合法 | 400 步（测试另跑 3×1500） | 真实 OrbitControls + 每帧约束 |
| C5 | 近平面四角在相机球内 | 角距 < R | 解析 |
| C6 | 每座门：眼高 1.6 m 的球沿 H14 路线（坡道/桥外端 → 门洞中心 → 45 m 外曲轮地面）全程合法且真的穿过门洞 | 1 m 栅格寻路、坡 ≤30%、离门洞中心 ≤ 门洞半宽；斜坡上眼高最多抬 0.3 m | Dijkstra 两段（起点→门洞、门洞→曲轮），0.25 m 复核 |
| C7 | 快速拖动/推拉/平移时相邻两帧球心的实际运动折线不与任何几何相交 | 5 个起点视角 × 120 步 | `move()` 记录的折线逐段 `segHit` |

结果：r4 C1–C7 全 0；同一套检查下 r2 相机：C2 2、C3 16、C4 60/400；r3 逻辑：C6 9/9、C7 11。

## 4. 路线图：下一批规则

### B. 道路与桥（web-r5）
把道路、坡道、木桥、土桥统一为**可步行表面网络**：节点 = 门洞中心、曲轮地面、城下；边 = 由门的 H14 路线和 OSM 道路（`highway`/`footway`/`bridge`，若 `data/osm.json` 有）派生的表面。
- **H15 网络连通**：每座门、每个围合曲轮地面、外部城下互相可达；无理由的断头路 = 违规。
- **H16 坡度与宽度**：纵坡 ≤ 参数、横坡 ≤ 参数，净宽 ≥ 门洞宽。
- **H17 桥的支撑与跨度**：桥面两端搭在地面桥台上；水中桥墩到达河床；每跨 ≤ 木梁跨度参数；桥面两端与道路高差 ≤0.1 m。土桥 = 土堤，两侧坡面稳定（坡比参数），坡脚落到堀底。
- **H18 净空**：步行表面以上净高 ≥ 人高 + 余量；木桥下水面/船行净空 ≥ 参数。另加正式的相机审计：从木桥下横穿。

### C. 地形修正（web-r6）
1.5 m 网格使石垣顶线和台地边缘呈锯齿台阶。改为：石垣顶线 / 台地边缘是精确折线（矢量约束），地形网格顺从这些折线（边对齐顶点、约束三角化或局部细网格）。
- **H19 边线一致**：渲染出的石垣顶线/台地边与其折线的最大偏差 ≤0.1 m，无台阶。
- **H20 排水与平整**：曲轮地面能排水到外侧，无积水坑；最大地面坡度 ≤ 参数。
- **H21 石垣勾配一致**：石垣面坡度在惯例范围内，顶线与脚线和高程一致。
- 保持 H11–H14 与相机审计为 0（相机碰撞使用修正后的地形）。

## 5. 维护约定
- 每轮前打备份 tag；结果更差或两次以上没有进展就 `git reset --hard` 回备份。
- 新规则必须：写入本文件（不变量/参数/容差/计算/理由）、加入面板与测试、用故障注入证明能报出违规、报告旧布局下的违规数。
- 加载时间不得比上一轮慢 20% 以上；脚本 `?v=N` 每轮递增。
